# Tag simulation and antenna boundaries

## LIS2DW12 data path

| Boundary | Implementation | Evidence in this checkout |
|---|---|---|
| Dataset | `hardware/models/lis2dw12/datasets/{static,walk,run,impact,random_movement}.csv` | Five deterministic, explicitly `SIMULATED` profiles; 128 XYZ samples at 12.5 Hz (10.24 s). |
| Conversion | `hardware/renode/scripts/dataset_to_resd.py` | Validates profile metadata and timestamps, converts g to µg, calls Renode `csv2resd.py`, checks generated stream values against source rows, rejects empty streams and values outside the sensor's ±16 g physical range. |
| RESD playback | `hardware/renode/src/RiosePeripherals.cs` (`LIS2DW12WakeModel`) | Profile RESD is loaded by the Renode model. Data-ready/FIFO/register behavior is tested through I²C. |
| Platform | `hardware/renode/riose_stm32l0.repl` | STM32L071 is used as a temporary surrogate for the target L031K6; this is not an exact MCU model. |
| Firmware | `hardware/firmware/src/tag_firmware.c` and `hardware/firmware/zephyr/src/main.c` | Zephyr I²C reads the output registers; firmware emits `SIMULATED_TRACE` IMU events in its configured logging path. |
| Current cross-boundary observation | `hardware/renode/tests/platform-smoke.robot` | With a fresh Zephyr ELF, attaches a terminal tester to `sysbus.usart2`, captures the firmware's `SIMULATED_TRACE` IMU_READ UART line, and checks all signed X/Y/Z mg values against the selected first RESD sample after register scaling. STATIC/WALK/RUN and a controlled golden axis probe are covered. |

The first incorrect boundary previously investigated was not an ignored RESD path in the current model. Existing register, wake and replay behavior was already present. The gaps were insufficient end-to-end evidence (the old suite covered only STATIC and WALK) and a Renode image with Zephyr logging disabled, so the C firmware trace callback never reached an observable console. The Renode config now uses Zephyr's minimal logger and structured trace option; Robot captures a genuine firmware UART line and checks X/Y/Z against the selected RESD input after register and mg conversions. STATIC/WALK/RUN traces are distinct and reproduced identically over two runs. `firmware-trace-capture.log` retains the captured lines; `firmware-trace-evidence.json` binds them to input and ELF hashes.

The independent `GOLDEN_AXIS_PROBE` fixture starts with X=+0.25 g, Y=-0.125 g and Z=+1.5 g; later samples vary X while holding Y/Z constant. Its RESD-backed firmware trace verifies axis order, negative sign handling, register quantization and the mg conversion. This is an engineering fixture, not an animal behavior profile.

RESD output uses the Renode tool's binary format. The converter validates data values, metadata and timestamps; source values are converted from g to µg. It rejects inputs beyond the sensor's physical ±16 g range. Tests cover source-to-RESD value preservation and firmware quantization for in-range probes. With firmware's configured high-performance 14-bit, ±2 g mode, Robot expects `int(µg / 244) * 4` per axis; firmware then interprets the signed 16-bit register words as 12-bit values and scales by 0.976 mg/digit. The ±16 g physical limit is from the [ST LIS2DW12 datasheet](https://www.st.com/resource/en/datasheet/lis2dw12.pdf). Profile hashes and observed trace/register values are recorded in `results.md` and the trace manifest.

## Antenna experiment and demo isolation

The active path is `hardware/antenna/run.py` → `geometry.py` → CSXCAD primitives → `openems_backend.py` → native openEMS. Completion validation requires matching spec/geometry/input hashes, energy convergence, mesh evidence, and hashed S11 and radiation artifacts. Current solver configuration is a 915 MHz Gaussian excitation, 401 linearly spaced frequency samples from 686.25 MHz to 1.14375 GHz, six `PML_8` boundaries, `NrTS=300000`, `EndCriteria=1e-5` (−50 dB in the solver warning), a λ/20 maximum cell at the upper band edge, feature-edge lines with 1.4 mesh smoothing, a 50 Ω z-directed lumped port, and an NF2FF box. The native Python bindings for openEMS and CSXCAD are installed; the native `openEMS` executable is at `/home/gusta/.local/opt/openEMS-0.37.0-rc3/bin/openEMS` and the runtime requires `OPENEMS_INSTALL_PATH` or `RIOSE_OPENEMS_EXECUTABLE` to expose it. Octave is not installed; this backend uses the Python bindings.

The current free-space candidate uses an assumed 82 mm four-turn planar meander (28 × 10 mm footprint, 1 mm zero-thickness PEC trace), a 30 × 48 mm finite PEC ground sheet and 0.5 mm feed gap. The free-space baseline excludes the PCB substrate and later scenario materials. The five configured scenarios add PCB, battery, enclosure and finally a homogeneous animal-proximity dielectric approximation. PCB, battery, enclosure and animal dielectric values are marked `ASSUMED`; the antenna is a parametric candidate, not a routed design. The geometry is generated from `hardware/spec.yaml`; no STEP/STL is imported. The animal case is not a tissue model.

Fresh current-branch runs use spec hash `3d3bf8c40183d2cd176cc54f6288af5114e6b36f2f3b5d2b0f811089de0d22cc`, geometry hash `cdf58104c6dc51e71a05bcfb4804c6a0042df0d8102c4ff1b1df65738c088fcb`, and input hash `5c90283be98a87d4d38862d8643de0e29db0b5f01b7a010fb4e0dfc3e9e2ffab`. The recorded mesh contains 45,864 cells (40 × 50 × 25 in the solver report; 39 × 49 × 24 intervals in mesh evidence), with maximum cell widths around 13.1 mm. A 40-second bounded run advanced 5,166 of 300,000 steps after 34.59 seconds, before the 42,362-step excitation. A second current-geometry run reached the configured −50 dB time-domain criterion at step 39,114 after 262.31 seconds (energy residual `1.2322e-6` versus `1e-5`). The runner then rejected S11 because its first frequency sample was +0.003734 dB. A diagnostic port calculation spans +0.003734 to −0.057452 dB across the sweep, with no in-band resonance resolved; no S11, impedance, gain or efficiency is accepted. The antenna is `PARTIAL_SIMULATED`, not a converged RF design.

An earlier 304,150-cell artifact was traced to a different geometry hash (`a2ac0942…`) and 143 mm trace route; it does not match the current 82 mm source geometry and is excluded. Earlier v1 stored outputs also had schema/input mismatch. An old pilot reported large adjacent-mesh S11 differences (11.095 dB and 10.302 dB) and resonance shifts (12.67% and 9.38%); those are historical diagnostics, not current accepted metrics. In the current free-space build, the trace XY bounds sit within the projected ground-plane bounds while the conductor is elevated 2.1 mm above the ground sheet and no substrate is present. This is a plausible geometry/topology cause for the near-total reflection, not a confirmed root cause; a reviewed feed/antenna design is needed before changing that geometry. The S11 check remains strict; no positive-dB value is clamped into a passing result.

The digital-twin CLI now supports `run --skip-antenna`. It labels both antenna stages `NOT_RUN` and `required: false`, omits them from required gate stages, and still records their status in the report. This provides an explicit way to run tag-focused demonstration stages without a long RF experiment. A default full-gate run still requires the antenna stages.

## Evidence boundary

All datasets, Renode interactions, firmware execution and openEMS work here are simulated. The Renode MCU is a family surrogate. OpenEMS numerical convergence, if achieved in a future run, would not establish antenna performance on a board, animal, or in a field. No hardware, sensor-accuracy, animal, field, or physical antenna validation is asserted.
